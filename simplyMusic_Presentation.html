Initial Architecture & Threats

  • Threat: CORS Misconfiguration & Direct API Exposure.
    Fix: Implemented Spring Cloud API Gateway as the single, strict entry point.
  • Threat: Hardcoded Users & Data Leakage.
    Fix: True Multi-Tenant Architecture. Data is now strictly siloed using the OAuth2 Subject ID (Tenant ID).
  • Threat: Exposed MinIO Object Storage.
    Fix: Streaming is now secured via on-the-fly, cryptographically signed, short-lived URLs.

Current Secure Architecture

Identity Provider (Keycloak): Issues secure JWTs and manages user lifecycles natively.
API Gateway: Validates JWT signatures and strictly routes traffic.
Tenant Context Injection: Gateway extracts the 'sub' (Tenant ID) and injects it into downstream headers.
Stateless Microservices: MongoDB and MinIO queries are strictly scoped to the injected Tenant ID.

Lifecycle of a Request

  1. Client initiates request to API Gateway with Bearer token.
  2. API Gateway validates the JWT via Keycloak public keys.
  3. Gateway enriches request with `X-Tenant-ID` and routes via Eureka.
  4. Backend Service queries MongoDB using Tenant ID to verify ownership.
  5. Backend calls MinIO to generate a short-lived presigned URL.
  6. Client safely streams audio directly from MinIO bypassing backend load.
